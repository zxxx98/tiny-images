# 全局提示词与公告设计

## 目标

在管理后台新增“设置”页，让管理员编辑全局提示词和公告。全局提示词默认留空，并在服务端统一前置到所有生成与图片编辑请求中。公告仅在 Playground 页面自动弹出；用户点击“知道了”后，当前浏览器在公告未更新前不再重复展示。

顶部现有跑马灯不在本次改动范围内。

## 数据模型

新增通用 `settings` 表，以键值形式持久化设置：

- `global_prompt`：全局提示词，默认空字符串。
- `announcement`：公告正文，默认空字符串。
- `announcement_version`：公告版本，默认 `0`。

读取不存在的键时返回上述默认值，不要求预先插入种子数据。保存设置时使用事务；只有公告正文实际变化才递增公告版本。全局提示词变化不影响公告版本。

## 服务端接口

新增管理员接口：

- `GET /admin/settings`：返回全局提示词、公告正文和公告版本，仅管理员可访问。
- `PUT /admin/settings`：接收完整的全局提示词与公告正文并保存，仅管理员可访问。

新增登录用户接口：

- `GET /v1/announcement`：返回公告正文和版本，仅要求有效用户身份，不暴露全局提示词。

接口接受空字符串，并保留管理员输入的正文内容；拼接提示词时仅用首尾去空白后的全局提示词判断是否为空。

## 全局提示词处理

全局提示词在统一执行入口应用，因此覆盖以下路径：

- 图片生成；
- 图片编辑；
- 同步、流式和后台任务调用。

当全局提示词非空时，发送给上游的提示词为：

```text
<全局提示词>
<用户提示词>
```

当全局提示词为空时，原样发送用户提示词。请求历史、后台任务记录、前端输入框和重试/复用操作始终使用用户原始提示词，避免管理配置泄漏或污染用户记录。

## 管理后台 UI

管理后台增加“设置”Tab，内容沿用现有 tiny-images 95 视觉体系：现有 `.card`、表单标签、textarea、`.btn primary`、成功和错误提示样式，不新增独立设计语言。

设置页包含：

- “全局提示词”多行输入框，并说明它会前置到全部生成和编辑请求；
- “公告”多行输入框，并说明留空时不会弹出；
- 一个主要“保存设置”按钮；
- 保存成功或失败的内联状态提示。

页面加载时读取当前值；保存期间禁用按钮，避免重复提交。

## Playground 公告体验

Playground 加载后请求当前公告。公告正文为空时不展示。公告非空时，将服务端版本与 `localStorage` 中已确认版本比较：

- 版本不同：自动打开公告弹窗；
- 版本相同：不弹出；
- 点击“知道了”：写入当前版本并关闭弹窗。

确认状态仅保存在当前浏览器，不绑定用户账号。管理员修改公告正文后版本递增，因此同一浏览器会再次展示。管理员只保存其他设置或重复保存相同公告时，不重复展示。

弹窗沿用项目现有复古窗口风格，包含清晰的“公告”标题、保留换行的正文和唯一主操作“知道了”。弹窗具有对话框语义、初始焦点和键盘可操作性；公告加载失败不阻断 Playground 的其他功能。

## 错误处理与安全

- 管理设置接口复用现有管理员鉴权；普通用户无法读取或修改全局提示词。
- 普通公告接口复用登录用户鉴权。
- 设置保存失败时保留编辑草稿并显示错误。
- 公告请求失败时静默跳过弹窗，不影响生图。
- 公告按纯文本渲染，不解释 HTML，避免脚本注入。

## 测试

服务端测试覆盖：

- 新数据库返回默认空设置；
- 管理员可读取和保存设置，普通用户无权访问管理员接口；
- 设置在数据库重开后仍然存在；
- 公告仅在正文变化时递增版本；
- 普通用户只能读取公告；
- 生成和图片编辑发往上游的提示词带全局前缀；
- 全局提示词为空时请求保持不变；
- 历史和任务仍记录用户原始提示词。

前端测试覆盖：

- 设置 Tab 加载、编辑、保存和错误状态；
- 空公告不弹出；
- 未确认的新公告自动弹出；
- 点击“知道了”写入本地版本并关闭；
- 已确认版本不再弹出，新版本再次弹出；
- 公告正文按纯文本和原有换行展示。

## 非目标

- 不修改顶部跑马灯；
- 不提供富文本或 Markdown 公告；
- 不做公告排期、历史列表或按用户分发；
- 不将公告确认状态同步到服务端。
