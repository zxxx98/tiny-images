# 历史图片交互与尺寸展示设计

日期：2026-09-01

## 背景与目标

历史详情弹窗中的图片当前绑定了进入 Playground 编辑模式的点击事件。用户点击图片进行查看时会被意外带到 Playground，图片查看与编辑入口的职责混在一起。本次只调整历史页，不改变 Playground 的编辑能力：

1. 点击历史详情中的图片保持在历史页并继续查看当前详情。
2. 只有明确点击“编辑此图”按钮时，才把图片带入 Playground。
3. 历史记录显示本次图片请求的尺寸。

## 方案

### 交互

`History` 的历史墙砖块继续打开详情弹窗。详情中的 `<img>` 改为纯展示元素，移除其导航点击处理和“点击进入图片编辑”的提示；“编辑此图”按钮继续调用现有的 `editImage` 导航。下载与超分按钮保持现有行为。

### 尺寸

历史 API 已返回记录的 `params`，普通生成和图片编辑的尺寸位于 `params.size`。前端新增一个纯函数统一格式化显示值：

- `params.size` 是非空字符串时显示它；未指定时显示 `auto`。
- 超分记录优先显示 `params.targetWidth` 与 `params.targetHeight` 拼出的输出尺寸，例如 `2048x1536`。
- 墙砖和详情元信息都显示 `尺寸: <value>`，使尺寸在不打开详情时也可见。

不新增数据库字段或接口字段，避免重复保存已经存在于历史参数中的数据。

## 错误处理

历史数据可能来自旧版本或手工记录。尺寸格式化遇到缺失、非字符串或不完整的目标尺寸时回退到 `auto`；图片过期处理保持现有“已过期”占位逻辑。

## 测试

- 前端回归测试验证点击详情图片后仍在 `/history`，且明确点击“编辑此图”仍导航到 Playground。
- 前端回归测试验证普通记录显示指定尺寸、缺省尺寸显示 `auto`，以及超分记录显示目标尺寸。
