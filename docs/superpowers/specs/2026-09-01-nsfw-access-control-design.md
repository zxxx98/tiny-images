# NSFW 模型访问控制设计

## 目标

为用户和模型映射增加独立的 NSFW 配置。只有管理员明确允许使用 NSFW 模型的用户，才能看到或调用标记为支持 NSFW 的模型映射。所有新增配置和数据库迁移后的既有记录均默认关闭。

## 已确认的权限语义

- `users.allow_nsfw` 由管理员在用户管理界面配置，普通用户不能自行修改。
- `models.supports_nsfw` 由管理员在模型映射界面配置。
- 未开启 `allow_nsfw` 的用户只能使用 `supports_nsfw = false` 的模型映射。
- 开启 `allow_nsfw` 的用户可以使用普通模型和 NSFW 模型映射。
- 管理员账号不自动绕过限制；管理员若要调用 NSFW 模型，也必须为自己的用户记录显式开启权限。
- 未绑定用户的 API Key 和未配置任何 API Key 时的开放模式没有用户级授权，因此禁止访问 NSFW 模型。
- 访问受限模型时沿用“模型不存在”响应，避免向无权限调用方泄露模型配置。
- 系统不分析 prompt 或图片内容。NSFW 判断完全依赖管理员维护的模型映射能力标记。

## 数据模型

新增 SQLite 迁移：

- `users.allow_nsfw INTEGER NOT NULL DEFAULT 0`
- `models.supports_nsfw INTEGER NOT NULL DEFAULT 0`

`UserRow`、用户管理 API 视图和前端 `UserView` 增加 `allowNsfw: boolean`。`ModelRow`、核心模型映射类型、种子配置类型和前端 `ModelMapping` 增加 `supportsNsfw: boolean`。

创建用户和模型映射时，字段缺省值均为 `false`。管理 API 的更新操作只在请求中明确提供布尔值时修改对应字段；非布尔值继续使用现有 400 校验风格拒绝。

## 统一访问策略

模型可用性由一个统一的路由访问策略表达：

```ts
interface ModelAccessPolicy {
  allowedChannelIds: number[] | null;
  allowNsfw: boolean;
}
```

路由器在现有渠道分组过滤之外增加 NSFW 过滤。候选映射必须同时满足：

1. 映射已启用，所属渠道已启用；
2. 映射所属渠道符合用户的渠道分组；
3. `policy.allowNsfw` 为真，或映射的 `supportsNsfw` 为假。

同一个对外模型名存在多条映射时，路由器只在符合策略的映射之间执行既有的优先级、轮询、熔断和故障转移逻辑。例如，同名模型同时有普通和 NSFW 映射时，未授权用户只会路由到普通映射；只有 NSFW 映射时则得到模型不存在错误。

调用方通过用户 ID 获取策略。用户不存在、用户 ID 为 `null`、未绑定 Key 和开放模式的 `allowNsfw` 都为 `false`。策略计算集中在仓储或服务端辅助函数中，避免每个入口自行解释默认值。

## 覆盖的入口

以下服务端入口必须使用同一访问策略：

- `GET /v1/models`：仅列出至少存在一条可用映射的对外模型名。
- `GET /v1/model-health`：只聚合当前用户可用的映射和线路。
- 同步图片生成和编辑。
- SSE 流式图片生成和编辑。
- 历史记录重新生成和重新编辑。

Executor 接收完整访问策略并交给 Router。所有实际调用均在路由层做最终授权，因此即使客户端绕过模型列表直接提交模型名，也无法调用受限映射。

## 管理界面

用户管理：

- 新建和编辑表单增加“允许使用 NSFW 模型”复选框。
- 新建表单默认不勾选。
- 用户列表增加 NSFW 权限状态。

模型映射：

- 新建和编辑表单增加“支持 NSFW”复选框。
- 新建映射默认不勾选。
- 模型列表增加 NSFW 能力状态。

普通用户界面不提供修改权限的入口。Playground 继续依赖 `/v1/models`，因此受限模型会自然从选择列表中消失。

## 种子配置与兼容性

`config.yaml` 的模型种子项允许可选的 `supportsNsfw`，缺省为 `false`。用户没有种子配置入口，首次管理员和后续管理员用户均按 `allowNsfw = false` 创建。

迁移对既有数据库安全：新增列为非空且默认 `0`，既有用户和模型不会因升级而获得 NSFW 权限或能力标记。现有客户端不发送新字段时行为不变。

## 错误处理与安全性

- 受限映射与不存在映射使用相同的 `ModelNotFoundError`，不暴露 NSFW 模型名。
- 管理 API 对 `allowNsfw` 和 `supportsNsfw` 使用严格布尔校验。
- 权限判断只信任数据库中的用户记录，不信任客户端请求体、JWT 自定义字段或 API Key 自带声明。
- 记录日志和历史时保持现有行为；未授权请求在触达上游前失败。

## 测试策略

遵循 TDD，按以下层次覆盖：

1. 仓储测试：迁移默认值、用户和模型创建/更新/读取、种子默认值及显式值。
2. Router 测试：未授权过滤、已授权放行、同名普通/NSFW 映射故障转移、无可用映射返回空。
3. 管理 API 测试：字段默认关闭、管理员可创建和更新、非布尔值返回 400。
4. V1 集成测试：用户、绑定 Key、未绑定 Key 和开放模式的模型列表与直接生成访问控制。
5. 流式、编辑和历史重试测试：确认所有执行路径在调用 provider 之前执行同一权限过滤。
6. 模型状态测试：只展示当前用户可访问的映射。
7. 前端测试：用户和模型表单默认值、提交字段及列表状态展示。
8. 最终运行服务端与前端全量测试，并运行完整构建。

## 非目标

- 不进行 prompt、上传图片或生成结果的内容审核。
- 不自动设置 AI Horde 的 `horde.nsfw` 参数。
- 不增加用户自助开启权限的设置页。
- 不改变渠道分组、额度、熔断或 Key 轮换语义。
